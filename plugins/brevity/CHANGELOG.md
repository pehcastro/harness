# Changelog

Versioned by commit SHA while the rules are still changing, so every push is an
update. An explicit version returns at 1.0.0 once they settle.

## Unreleased

### Added

- Countable caps in the rules: 40 words for a status, 80 for an answer, 60 plus
  15 per agent when reporting delegated work, 150 for a session summary. This
  was the single largest change measured, cutting replies 37% on a 28-turn run
  and taking scorecards to zero.
- A rule for reporting delegated work. Replies about subagent output averaged
  178 words against 79 for everything else.
- A statement that the rules do not expire, and that the model's own earlier
  long replies are not a precedent.
- Two hooks. `remind.sh` runs on every prompt and reports the measured average
  length of recent replies, escalating to a re-read of the rules when they drift
  far. `lint.sh` runs after every reply and asks for a rewrite when it breaks a
  rule a machine can count. Both are POSIX sh and awk with no runtime.
- `hooks/reminder.txt`, generated by `build.sh` from `rules/core.md`, so the
  hook holds no second copy of the caps.
- Benchmarks at 72 and 140 turns. Shorter suites cannot see drift.
- `CHANGELOG.md`.

### Changed

- Version is the git commit SHA rather than a pinned `0.1.0`. Pinning meant a
  pushed rule fix reached nobody, because Claude Code uses the version string as
  its cache key.
- The banned word list dropped from 53 terms to the ones that actually appear,
  each qualified by sense. `alignment`, `robust`, `cadence`, `surface area` and
  others were removed because they have real technical meanings, and banning the
  letters was wrong more often than right.
- `just`, `actually`, `really` and `simply` left the hedge list for the same
  reason.

### Fixed

- Windows paths in both hooks. `TMP` is a backslash path and awk's `-v` was
  eating the separators. Paths now pass through the environment instead.
- Em dash detection uses a string rather than a regex literal, since POSIX
  guarantees octal escapes in strings but not in regex.

### Known

- Reply length still grows over a long session. The rules set where the climb
  starts and the hooks flatten it, but nothing removes it.

## 0.1.0

First working version.

### Rules

- 93 banned terms across status words, consultant words, self-praise, openers,
  closers and hedges.
- 17 banned behaviors, from preamble through to unrequested offers.
- ASD-STE100 Simplified Technical English for replies longer than about three
  sentences.
- `WARNING`, `CAUTION` and `NOTE` replace softened warnings. `CAUTION` is
  mandatory before anything that cannot be undone.
- Three rules protect information from the cutting rules: keep the information,
  say what you changed, and correct a wrong premise before acting on it.

### Packaging

- Claude Code output style with `force-for-plugin`, so it applies without a
  `/config` step.
- Generated rule files for Cursor, Windsurf, Cline, GitHub Copilot and
  `AGENTS.md`, all built from `rules/core.md` by `build.sh`.
- A corpus skill holding 154 worked examples, loaded on demand rather than every
  turn.
- An optional POSIX `sh` status line wrapper that shows the active output style.

### Tested

- A 10-turn session measured with and without the plugin: 84% fewer words, 59%
  fewer output tokens, 31% lower cost.
- A hard suite of 10 scenarios where the rules could do harm rather than save
  words. It found the em dash rule failing on list labels, and the two missing
  rules about changes and wrong premises.
